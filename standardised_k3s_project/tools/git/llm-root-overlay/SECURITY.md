# Security

Report a suspected secret exposure or security defect privately. Do not put credentials, session data, recovery grants or exploit-sensitive deployment details into a public issue. Use GitHub's private vulnerability reporting for this repository where available. There is no security-response SLA.

Trust boundaries are described in the software design and extensions guide. Application agents do not inherit host administration. GPU transitions require the controller. Worker requests require exact project/source/parent identity and bounded execution. Private recovery grants are not source configuration.

The source export excludes runtime secrets and history and uses a heuristic credential scan plus targeted review. That is not a formal security audit. Internal topology is deliberately retained for the private operator repository and must be reviewed again before public publication.

The exported SearXNG manifest contains a deployment placeholder; provision a private value before exposing a deployment. Do not use example credentials, disable authentication, bypass release fences or manually clear ownership state.

This publication does not rotate production credentials, change network policy or activate a release. Follow the established owner-controlled incident/recovery process when responding to an actual exposure.
