Best prompts for SDXL

Composition and style keywords

SDXL responds well to a short subject clause followed by comma-separated style/quality tags, roughly in order of importance: subject & action, setting/background, lighting, camera/lens framing, then quality boosters. Example:

a weathered stone lighthouse on a cliff at dusk, dramatic orange sky, waves crashing below, wide-angle shot, highly detailed, sharp focus, 8k

This works because SDXL's text encoder weighs earlier tokens more heavily and tags act as independent "knobs" rather than a grammatical sentence — stacking unrelated clauses with commas is normal and expected, unlike natural-language prompting for a chat model.

Negative prompts

Negative prompts remove the model's common failure modes rather than "oppose" the positive prompt. A sound general SDXL negative baseline:

low quality, blurry, deformed, extra limbs, extra fingers, bad anatomy, watermark, text, jpeg artifacts, oversaturated

Add subject-specific negatives (e.g. plastic skin, mannequin for portraits) rather than a huge generic list — an overloaded negative prompt pulls the model toward a bland "average" image.

The installed NSFW-3D checkpoint

Whichever model is installed under this role in Model Manager is a checkpoint fine-tune, so it already carries its own stylistic bias (often a stylised 3D-render look) without extra trigger words — treat it like the base checkpoint for prompting purposes, and prefer its own model card/README (if Model Manager's Inspect step surfaced one) for any checkpoint-specific tags.

The 3d-animation-style-sdxl LoRA

Trigger words are unconfirmed for this specific LoRA — its Hugging Face page (thejagstudio/3d-animation-style-sdxl, base stabilityai/stable-diffusion-xl-base-1.0) does not publish one. General, sound guidance for an unconfirmed SDXL LoRA:

  • Start at LoRA weight 0.6–0.8 (not 1.0) and raise it only if the style is too weak; most SDXL style LoRAs over-saturate or distort anatomy above ~1.0.
  • If the LoRA's author did publish a trigger word/phrase, put it early in the prompt, close to the subject — LoRA triggers usually act like a style tag the fine-tune was trained to associate with its look.
  • Without a confirmed trigger, describe the desired look directly instead of guessing one (e.g. 3D animated movie style, Pixar-like rendering, soft global illumination) and compare against the LoRA's gallery images on its model card to judge whether it is actually engaging.
  • Combine with the base checkpoint, not the NSFW-3D checkpoint, unless you have confirmed the LoRA was trained against that checkpoint's distribution — a LoRA fine-tuned against one SDXL checkpoint can look subtly different merged onto another.

Best prompts for MOSS Image Studio

The look, scene, look wrapping convention

Each of the Studio's 52 presets is recipe text (the "look") that gets said once before your scene and once again after it, plus the recipe's own negative prompt is appended automatically. Write only what is physically in the picture — subject, pose, setting — and leave grain, colour cast and lens character to the preset; repeating that styling yourself fights the preset instead of reinforcing it.

Representative presets (curated and licensed — see MOSS's own page for the full 52)

These are a sample across the Studio's four categories; the complete, authoritative list with full recipe text is in MOSS Image Studio itself under "Camera / film look":

Holga (Cameras) — Square photo centered in the frame, with wide solid black bars on the left and right…
Warm golden (General looks) — Warm golden color, honey-toned highlights, soft amber shadows, gentle film grain.
Faded 1970s print (General looks) — Faded 1970s photo print, washed out colors drifting toward orange and magenta…

Best prompts for Mesh generation

What the model actually produces

LLaMA-Mesh is a language model fine-tuned to emit a Wavefront OBJ (plain text v/f lines) as its chat completion, not an image-conditioned 3D model. Treat it like prompting a careful, literal-minded text model for a structured file, not like an image generator.

Keep it short, simple and low-poly-biased

Ask for one concrete object with a simple silhouette; the model writes better geometry for forms it can describe as a small number of primitives than for intricate or highly detailed scenes. The project's own verified acceptance run used exactly this kind of prompt (an 8-vertex, 12-face cube), and its production skill guidance uses:

Create a simple low-poly rounded rock. Return one complete Wavefront OBJ mesh with valid vertices and triangular faces.

Useful patterns: name the object plainly ("a simple wooden chair", "a low-poly pine tree"), ask explicitly for triangular faces (the validator requires a clean, finite, properly-indexed mesh), and avoid asking for multiple unrelated objects, articulation, or fine surface detail in one prompt.

Honest limits — do not overclaim fidelity

The pipeline's own acceptance record describes its output as "generated prototype geometry without authored UVs or textures." Expect a rough, unrigged, untextured mesh suitable for silhouette/blockout review — not a game-ready asset. Every generation here would also go through the existing Blender cleanup/validation stage before a GLB is produced, exactly as the pipeline already does; nothing about that validation is changed by this page.
