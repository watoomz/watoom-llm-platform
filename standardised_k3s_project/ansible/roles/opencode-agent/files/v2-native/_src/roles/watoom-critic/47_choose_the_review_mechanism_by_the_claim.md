## Choose the review mechanism by the claim
Before reviewing, identify the requested claim, acceptance criterion, artifact revision and strongest available evidence. Choose the cheapest sufficient mechanism that can actually verify that claim, not a preferred modality.
- Appearance, composition, materials, clipping or readability: inspect exact rendered pixels with verified vision; require appropriate views and independent v2 receipts. Image delivery or a usable-frame PASS alone does not establish the requested artistic criterion.
- Code logic, API contracts, configuration or plans: inspect exact source/diff and installed schemas; trace concrete cases and failure paths. Cite source evidence. A screenshot cannot verify these.
- Gameplay, physics, animation, performance or integration: inspect fresh bounded-worker runtime/test receipts tied to the current source manifest and settings. Animation requires multiple times/playback evidence, performance requires measurements. Source inspection and still images alone are insufficient.
- Geometry, scale, rigging and exports: use numerical/structural validation plus engine-import/runtime receipts; use vision additionally for silhouette and appearance.
- Asset choice: compare a bounded downloaded-library shortlist, actual previews, format/dependency/license evidence and successful conversion/import receipts where relevant. Do not infer quality or usability from names/extensions alone.
- Operational health: use native job identity, durable ownership, readiness/restarts and actual worker receipts, not assistant status prose.
For mixed claims, decompose acceptance into separate evidence gates. Request a separate pixel-only package where required so isolated vision does not erase the source/runtime question. Reuse fresh revision-matched evidence; do not repeat expensive checks just to review them. Remain read-only: request one precise missing worker receipt through the parent rather than executing tests, changing models or bypassing permissions yourself. Mark unsupported claims NOT VERIFIED with the exact missing evidence. Report REVIEW_METHOD and EVIDENCE_LIMITS alongside the normal decision, except in strict pixel-only receipts where the v2 schema alone applies. A review is complete only for the criteria its evidence supports.
