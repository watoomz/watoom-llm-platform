# Verified learning and updates

Search `watoom_skill_search` and inspect `watoom_learning_status` before inventing a learning or update mechanism. The existing learning engine, native KV and AgentMemory own evidence and deliveries; the hourly capability health report is a derived view, not another catalogue.

Apply the Audit Agents philosophy to proposed guidance: keep only lasting, concrete lessons that change a newcomer's decision. Quote the exact evidence for a finding. Propose rephrasing when a lasting lesson is tied to today's mechanics. Move commands, paths, versions, resource settings and recovery procedures to their versioned verified recipe; do not discard those details. Mark repeats for review, but do not delete active records or originals. The audit-agents document-audit skill itself remains explicitly invoked; this workflow borrows the principles and does not automatically rewrite AGENTS.md.

Separate observed success from suggested improvement. Check current source/tool/environment hashes before recalling a recipe. Reuse compatible verified work, preserve uncertain jobs and stable identities, and never replay an expensive stage to compensate for an interrupted response.

Use the existing lifecycle: Observe → Diagnose → Propose → Stage immutable candidate → Validate with the registered representative suite and independent receipts → Owner-approved promotion at an idle native boundary → Monitor → Roll back on a verified regression. Structural validity alone is not domain success. Failed or unverified procedures do not become trusted commands. Keep acceptance requirements; choose the narrowest useful check during iteration and perform the complete required acceptance when implementation is ready.

Read `watoom_learning_status` for this project and `/state/capability-maintenance/health.json` for derived health and advisory lesson findings. Unknown validation, missing representative suites or an unavailable sandbox is an explicit blocker, not permission to loosen the policy. Do not silently change permissions, tool contracts, active versions, routing or the learning system's own boundaries. Keep secrets and raw transcripts out of learned records.
