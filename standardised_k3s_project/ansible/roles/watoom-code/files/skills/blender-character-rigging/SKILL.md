# WatooM production: blender-character-rigging

Use the existing watoom-workflow -> watoom-builder serial hierarchy. Load this skill on demand. Production uses pinned Blender 5.2.1 after CPU compatibility qualification. Inspect actual APIs; the retained 4.2 runtime is rollback-only.

Use installed scripts through a verified external worker with pinned Blender 5.2.1. In a game project that worker is the native `watoom_game_worker` operation `blender`: write `.opencode/blender-jobs/<job>/request.json` with `script` `skill:<this-skill>/scripts/<file>.py`, optional `blend` and `args` (`{out}` is the writable output folder), then request it; the receipt gives the script's @@JSON@@ result, traceback and output files (see watoom-blender-asset-builder). The server profile uses CPU, 4GiB and two threads; the RIG profile uses an 8GiB Windows Job Object, four threads and OptiX (or explicit CPU). Component stages have a maximum 300-second deadline. The 2GiB application shell must never execute non-dry-run Blender stages. GPU-context checks run on a qualified RIG context and may skip only on the CPU profile; a skip is not GPU qualification. Preserve acquired sources and versioned outputs under /data/ai/projects/llm/pipelines/blender-asset-builder/<revision>. Do not install inherited addons/MCP/software or use the inference GPU. Changed scripts, inputs or execution profiles invalidate resume validation; inspect retained failures and use at most one explicit --retry-failed. Follow references/worker-execution.md.

Scripts: auto_fit.py, bind_mesh.py, creature_fit.py, creature_rig.py, rig_check.py, rigify_build.py, stress_poses.py.

Tailed bipeds (theropod dinosaurs, raptors, ground birds; static statues and scans included): use `creature_rig.py -- --source <fbx|glb> --name N --length <metres nose-to-tail> --save N_rigged.blend`, not rigify --add auto (it picks 'bird' and grades these poor: wings on the small arms, a staggered statue pose throws the facing off). It turns the mesh to face -Y with the feet on Z=0, fits a 22-bone engine skeleton from surface landmarks (creature_fit.py: legs traced up from each foot, centreline through the wide body core so sails/crests are ignored, each foot's largest ground patch so a hand on the ground is not a foot) and skins with bind_mesh. Every bone's local X is the lateral axis. Then blender-pbr-materials build_pbr_material.py for the textures and blender-animation creature_gait.py for the clips. Check the fit in a side render with the bones drawn (2026-11-19: T-Rex, Spinosaurus and a scanned theropod, T-0023). creature_fit.py is pure numpy: python3 -m unittest test_creature_fit.

Automatic rigging of an unrigged mesh (humanoid, quadruped or bird; no manual joint placement): `rigify_build.py -- --add auto --auto-fit [MESH ...] --generate`, then `bind_mesh.py`. It detects body type and facing, places every joint from mesh landmarks and reports `auto_fit.quality` (good / review / poor) and `quality_score`, graded from geometry alone: E = the worst of limb-chain distance outside the mesh, distal leg-axis offset and left/right height difference, in % of height (good E<=4, review 4-8, poor >8; score = 1-E/12). `score_fit` can re-grade after manual joint edits without refitting. Validated 2026-11-06 against original rigs (% of height, mean joint error): humanoids 0.7-3.3, quadrupeds 3.4-4.6 (front shoulder 5.3-8.5), bird 6.7 (reviewed: wing clearance 6.3%). On review/poor, render the metarig in x-ray and correct joints before generating. `bind_mesh.py` welds duplicate vertices by default (size-relative tolerance, within each mesh, so split-vertex meshes no longer tear apart when animated); pass `--no-weld` when coincident disconnected surfaces are intentional. Plain `--fit` only scales; it does not place joints. Retarget animation onto the generated rig with sims4-animation `retarget_generic.py`, passing `--target-armature` explicitly (auto-pick can choose the metarig). Inspect script help and current APIs before choosing parameters. CLI scripts print @@JSON@@; inspect ok/pass as well as exit status. Save and hash source checkpoints after each stage.
