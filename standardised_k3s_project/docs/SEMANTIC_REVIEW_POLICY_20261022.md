The owner's terrain capture contradicted the job's observations. The pixels were delivered correctly, but long scene history/expected descriptions contaminated the review. Correct transport and a well-formed receipt did not establish accurate perception.

## General behavior
Every pending verified visual review now uses a deterministic isolated image-only model request: prior task messages and author claims are omitted, while the exact matched image bytes are retained. The request keeps only the already permitted native write tool, never grants new execution, and forces one receipt write; read-only roles return strict JSON. No additional review model call is introduced. Only this pending-image step is isolated; the ordinary task context resumes afterward.

Version2 receipts require visible facts, framing usable/issues and uncertainties. Technical speculation is excluded from pixel observations and the inferences array is constrained empty. Poor framing cannot PASS. A PASS is explicitly a model-reported single-frame assessment, not independent correctness, rig/animation validation, source identity, engine acceptance or full project completion. Relevant criteria, views/playback and runtime receipts remain separate. Legacy cached reviews do not suppress a new v2 review or count as v2 evidence; history is retained. Human contradiction invalidates use of the old claimed approval until reconciled.

All five maintained roles carry these rules, including separation of facts, hypotheses and verified technical causes. No asset transforms were undone based solely on a new model opinion. The project's operator audit flags the contradicted terrain report and provisional older semantic approvals.
