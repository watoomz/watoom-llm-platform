# Blender application-shell protection and 4 GiB worker routing
An application-container OOM restart left a root/child session tree suspended with a persisted running shell call. Read-only evidence showed a direct background Blender command without the external worker wrapper. The application container, not the external render worker, was OOM-killed. No engine process remained after restart. No new render was launched during this repair.

The maintained coordinator guard now rejects direct Blender startup in native shell tools, including scene inventory, posing/preparation and rendering. This prevents the observed routing mistake before loading a heavy scene in the application cgroup. Runtime/version identity can be read from installed manifests. Common direct command, absolute/quoted path, environment/timeout/exec wrapper and nested static shell forms are covered. This command classifier is a routing guard, not a complete shell security sandbox; opaque external scripts still require correct worker admission and inspection.

The general capture procedure and workflow/builder rules require the verified external worker capped at 4 GiB (MemoryMax=4G), including scene loading/preparation. Worker profile/receipt must prove the bound. A missing worker operation must be reported explicitly; no memory argument may be invented in an unrelated fixed native schema and no fallback to the application shell is allowed. Application memory and inference configuration were not increased.

The existing guarded render-routing coordinator accepts optional --update-shell-guard, installs a versioned immutable guard with the maintained role task and selects its verified config path. Previous config/agents/skill trees and a consistent SQLite snapshot are retained for scoped rollback. No app restart or image replacement is required. Repeat activation was unchanged.

Crash reconciliation: tools/watoom-code/recover-restarted-claims.py uses restarted_claims.py. It requires exact selected root-tree claim identities/timestamps, current-container identity and last terminated container proof of OOMKilled/137, no newer work, no active engines/jobs/native leases, no pending inputs/other durable ownership, native admission fencing and a consistent database snapshot. Transactional compare-and-swap marks only that old root/tree interrupted and releases suspension/retry flags. History, original time_updated ordering and user artifacts remain; no prompts/jobs are resumed and no whole database is restored.
