# Native memory lifecycle, ownership observations and skill catalogue

Memory knowledge remains in AgentMemory. Corrections, supersessions, consolidations and withdrawals are append-only scoped native envelopes with original ids and reasons; originals remain auditable. Native recall filters superseded/withdrawn records and resolves successors from AgentMemory. The existing app checkpoint/outbox journal owns delivery, operation ids and retries; there is no second semantic-memory database.

Use /memory-correct, /memory-supersede, /memory-consolidate or /memory-withdraw with JSON {requestID,targets,summary,reason}. Targets are native envelope ids in the current project/repository/agent scope, with observed backend receipts. Reuse the exact requestID/payload after uncertain outcomes. Conflicting retries and cross-scope changes are rejected. Consolidation accepts a source-backed summary; it does not run the installed backend's broad LLM consolidation pipeline, which does not enforce the same repository/agent boundary.

watoom_memory_record captures a goal, milestone, decision or safe-stop handoff with confidence, source references and next action. Native lifecycle checkpoints independently cover execution, child creation, pre-tool calls, tool outcomes, steps, compaction outcomes and interruption. No transcript, tool input, credential or raw output is copied into automatic semantic envelopes. Mandatory mode WATOOM_MEMORY_REQUIRED=true rejects missing endpoint configuration. Backend outage retains the transactional outbox and explicit uncertainty; inference is not required to checkpoint. Recall outages are visible and do not mean empty history.

The /memory view and authenticated /api/memory/status report operational counts, timestamps, retrieval failures/latency, checkpoint ids and read-only ownership. Historical rows retain unknown timestamps; observed receipts do not claim fsync durability. GPU observations are atomically published by the existing controller from persisted state and request accounting; they cannot mutate models. App access is a read-only directory mount, with root ownership and freshness checks. No controller socket or scaling permission is given to the app.

The /catalogue view and /api/skill/index show short descriptions of the live installed skills and prompt-builder pipelines. Model tool watoom_skill_search uses the same index. Native context ranks the current task and loads strongly matched instructions only when permissions already allow it; an ambiguous or denied workflow is not executed. Ranking is lexical/document-frequency based with bounded body evidence and spelling variants, not an embedding model or a claim of perfect semantic understanding. New skill files enter through native discovery; catalogue results are rebuilt from current installed records without a hand-maintained list.

Optional per-skill metadata is a JSON fenced skill-routing block containing aliases and requires (skill ids). Existing prompt-builder pipeline blocks also supply title/description, keywords, requires and availability. Metadata is parsed as data only. Missing dependencies, explicit-only dependencies and cycles are reported; they do not enable installation or broaden permissions. Existing generation approvals and worker guards remain authoritative.

Deployment must preserve current databases and take a verified backup before the additive timestamp migration. No destructive downgrade is provided: older images ignore additive columns. Use a pinned candidate, existing deployment guard and a verified idle controller boundary. The scoped observability playbook does not deploy a router, alter inference or change GPU power. Restart/rollout policy in the application repository still requires operator resolution before live activation. Validate the candidate UI/API and native service tests before promotion.
